# Trace Format v1 — Session Metadata

Normative specification of the session metadata object (`meta.json`).
Implements §7.8 of the Starforge design spec. The Rust implementation is
`starforge-format::SessionMeta`; the JSON Schema is `schema/session-v1.json`.

## Encoding

Session metadata is a single UTF-8 JSON object. Timestamps are RFC 3339
strings. The session identity is a ULID, generated by the CLI so commit
trailers can be written before upload; identity is `(repo, ULID)`.

## Fields

| Field | Type | Notes |
|---|---|---|
| `format` | string | Must be exactly `"starforge.session/v1"` |
| `id` | string | ULID |
| `agent` | object | `{name, version}`; `name` is one of `claude-code`, `codex`, `pi`, `opencode`, `gemini` |
| `models` | string[] | Models observed in the session |
| `title` | string? | Agent-provided title or first prompt excerpt; absent when unknown |
| `started_at`, `ended_at` | RFC 3339 | `ended_at` absent while receiving |
| `repo` | object | `{remote_urls[], branch, head_at_start}` |
| `parent_id` | string? | Parent session ULID for subagents; absent otherwise |
| `usage` | object | `{input, output, cache_read, cache_write, reasoning}` token totals; each defaults to `0` when absent |
| `files_touched` | string[] | Repo-relative paths |
| `redaction` | object | `{fingerprint, counts{detector: n}}`: rule-set fingerprint plus per-detector match counts |
| `capture` | object | `{mode: "hook" or "discovery", cli_version, adapter_version_verified: bool}` |

`usage` counters are unsigned integers and default to `0` individually, so
older writers that omit a counter still parse.

## Validation

`SessionMeta::parse` rejects:

- wrong `format` tag → `BadFormatTag`;
- unparsable `id` / `parent_id` → `BadUlid`;
- unparsable `started_at` / `ended_at` (not RFC 3339) → `BadTimestamp(field)`;
- unknown `agent.name` → `BadAgent(name)`;
- malformed JSON → `Json`.

## Evolution rules

Adding optional fields does not change the format major version; readers
ignore unknown fields. Removing or retyping a field, or changing a field's
meaning, requires a new major version. The server reads every published
major version indefinitely.
